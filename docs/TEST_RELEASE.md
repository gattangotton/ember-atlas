# 限定テスト公開の手順

対象：v0.3、参加者用の共通パスワード＋管理者専用パスワード、個人データは各ブラウザーに保存。

## 起動方式

普段のPC内利用は `npm start` または `起動.ps1`。従来どおり `http://localhost:5174/` で開き、ログインは不要です。保存先を変えないため、以前と同じブラウザー・URLを使ってください。

Web版は **Nodeサーバーを1プロセスで動かせる環境とHTTPS** が必要です。静的ファイルだけを配信する方式では、今回のログイン制限は働きません。`public/` を別の経路で公開せず、すべてのリクエストを `server.mjs` に通します。

公開先の秘密情報設定で、次の環境変数を設定してください。実際のパスワードをソースや共有資料に記載しないでください。

| 設定 | 値 |
| --- | --- |
| `NODE_ENV` | `production` |
| `ACCESS_MODE` | `password` |
| `APP_ORIGIN` | 公開先の正確なHTTPSオリジン。例：`https://atlas.example.com`。パスなし |
| `TEST_USER_PASSWORD` | 参加者用。16文字以上、最大1,024バイト |
| `TEST_ADMIN_PASSWORD` | 管理者専用。参加者用と異なる16文字以上の値 |
| `PORT` | 公開先から指定される待受ポート。省略時5174 |
| `HOST` | 通常 `127.0.0.1`。コンテナの内部待受が必要な環境は `0.0.0.0` |

起動コマンドは `npm start`。HTTPSの終端処理は公開先のリバースプロキシで行い、Nodeの待受ポートは外部に直接公開しません。アプリはサイトのルート `/` に配置します。Cookie付きの応答をCDNで共有キャッシュしないでください。

本番モードの認証なし起動、認証なしの外部向け待受、不完全なパスワード設定、HTTPの公開URLは起動時に拒否します。HTTPSの証明書や転送設定そのものはホスティング環境側で用意する必要があります。

## 参加者と管理者

- 参加者：公開URLを開き、「参加者」を選んでログイン。所持・育成・研究・建設・計算・バックアップを利用します。
- 管理者：`/admin.html#admin` から管理者用パスワードでログイン。共通値、画像、確認資料、共通データの入出力を扱います。
- 参加者のセッションでは管理者HTMLを取得できません。画面のボタン非表示とは別に、サーバーで制限します。
- 管理者編集も現在のブラウザー内に保存されます。各参加者へ自動配信する機能はありません。確認済みの共通データを書き出し、リポジトリ側へ取り込み、検証して再配信してください。
- 個人データをサーバーへ送る保存APIはありません。同じブラウザーの「プレイヤー切替」は記録の整理機能であり、本人認証ではありません。

## セッションと運用

セッションはランダムな不透明トークンを使い、サーバーのメモリーに保持します。本番Cookieには `Secure`、`HttpOnly`、`SameSite=Strict`、`__Host-` 接頭辞を付けます。ログイン時にトークンを更新し、ログアウト時はサーバー側でも無効にします。認証の送信元を照合し、パスワードはソルト付きscryptで照合します。方式の参考：[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

最大8時間、サーバーへの最終アクセスから30分で失効します。表示済みの画面のローカル編集は即座には止まりませんが、戻ってきたタブや新たな読込ではログイン状態を確認します。サーバー再起動で全員ログアウトします。複数プロセスへの拡張には共有セッション保存先が必要です。

失敗試行は接続元単位で15分に10回まで。転送ヘッダーは信用せず、プロキシ経由では同じ接続元として制限されます。小規模テスト向けの保守的な設定です。公開先でもアクセス制限を設定し、必要なら信頼するプロキシ構成に合わせて調整してください。参加者の正常ログインでは管理者の失敗回数を消しません。

共通パスワード方式は参加者を個別に停止できません。漏れた場合はパスワードを変更し、サーバーを再起動して再案内します。ログアウトしてもブラウザー内の育成記録は残ります。共有PCでは別のブラウザープロファイルを使ってください。

## 公開URLでの最終確認

1. 未ログインでアプリ・共通JSON・管理者画面を直接開き、ログイン制限が働くこと。
2. 参加者ログインで所持品保存・バックアップ・復元ができ、管理者画面には入れないこと。
3. 管理者ログイン、ログアウト、ログアウト後の再アクセスが正しく動くこと。
4. HTTPS、Cookie属性、HTTPからHTTPSへの転送、共有キャッシュされないこと。
5. PCとスマートフォンで使い方ガイドと主要画面を開くこと。
6. ローカルの既存記録を引き継ぐ人には、元の画面でのバックアップと公開URLでの復元を案内すること。

ローカル検証ではサーバーの制御と画面動作を確認済みです。公開先・ドメイン・本番パスワードの設定および公開環境での上記確認は、公開先決定後に実施します。
